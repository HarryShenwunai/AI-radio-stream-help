# 可自助导入角色：画师、拆件、绑定与开发交付基准

日期：2026-11-12，Europe/London。状态：官方资料研究与项目建议，未委托画师、购买素材、下载SDK、运行模型或修改UI。目标是用户能导入自己的合法角色，示例角色只作测试，不限定可选角色数量。

## 结论与“配比”的解释

这里把配比分成三件事：角色的视觉比例、制作文件与功能的配套关系、各工种的工作量与预算分配。用户尚未指定画风、头身比、画师或预算，以下不替用户选择。

应先确定应用能接收的运行格式和能力，再给画师/绑定师交付单。制作源文件与运行包分别验收。自助导入应读取常见运行包，由应用向导生成自己的映射；不要求每位画师预先掌握本项目的JSON。

单张立绘可以作为静态角色；细致Live2D动作通常需要拆件和绑定工作。上传PSD或PNG不代表已经取得可直接运行的动态模型。官方教程也区分插画处理、拆件、建模与动画步骤。[官方插画处理教程](https://docs.live2d.com/en/cubism-editor-tutorials/psd/)

## 1. 已核实的官方要求

| 对象 | 官方文档支持的事实 | 对本项目的含义 |
| --- | --- | --- |
| Cubism导入PSD | PSD、RGB、8bit/channel为导入条件；官方建议sRGB；导入用部件应处理合并及遮罩 | 这是给制作人员的要求，不是应用用户必须上传PSD |
| 拆件与补全 | 可动部件分开，补画原图中被遮住的范围 | 根据要做的动作决定拆分范围；静态预览好看不代表转头/张嘴不破图 |
| 工程文件 | `.cmo3`是模型制作工程，`.can3`是动画工程 | 属于制作/返修交付；不作为首版运行包入口 |
| 运行导出 | 默认导出`.moc3`、`.model3.json`及纹理；其他设置按选项导出 | 运行包要保留引用的相对路径与所有必要文件 |
| 口型/眨眼 | `.model3.json`可用Groups声明LipSync/EyeBlink的参数映射 | 先读模型映射，再提供手动修正；不强制所有上传者采用同一参数ID |
| 目标版本 | 导出目标按嵌入SDK选择；新工程不保证被旧Editor打开 | 固定Editor、导出目标、Core/Framework/renderer版本矩阵 |

来源：[PSD注意事项](https://docs.live2d.com/en/cubism-editor-manual/precautions-for-psd-data/)、[文件类型](https://docs.live2d.com/en/cubism-editor-manual/file-type-and-extension/)、[运行导出](https://docs.live2d.com/en/cubism-editor-manual/export-moc3-motion3-files/)、[口型](https://docs.live2d.com/en/cubism-sdk-manual/lipsync/)、[目标版本](https://docs.live2d.com/en/cubism-editor-manual/target-version-selection/)。均于2026-11-12查阅。

上述是文档事实，未在本项目实际导入。头身比、画布尺寸、图集张数、表情数量和工种预算比例不是这份官方资料给出的统一产品标准。

## 2. 项目能力分级：建议基准，不是行业强制标准

| 档位 | 用户可自行提供 | 最低验收 | 增强能力与缺项处理 |
| --- | --- | --- | --- |
| 静态立绘 | 具有透明背景的PNG；其他格式待单独确认 | 图像能解码、透明边缘正常、缩放与位置可恢复 | 可另配眨眼/说话状态图；只有一张时保持静态，不伪造动态绑定 |
| Live2D基础显示 | 兼容的`.model3.json`、`.moc3`、引用纹理 | 引用闭合、版本支持、默认姿态可见、可释放后重新加载 | 无物理/动作/表情仍可显示；分别标为缺少相应能力 |
| Live2D说话增强 | 基础包加LipSync映射，或用户向导里选择参数 | 音频播放驱动口型，停止/取消后回到静止状态 | 只有音量驱动时称口部开合，不声称音素级同步 |
| Live2D表情/动作 | 声明并引用`.exp3.json`、`.motion3.json`与相关设置 | 每个映射可独立预览、复位、停止，不越参数范围 | 未映射事件不播放；缺项降级，不因缺“高兴”动作拒绝整个角色 |

`ParamMouthOpenY`、`ParamMouthForm`、`ParamEyeLOpen`、`ParamEyeROpen`来自官方标准参数表，是便于复用的推荐约定；实际模型可以有不同范围或ID。应用需读取实际范围并规范化，不能把0–1或某个英文ID写死为所有模型唯一可能值。[标准参数表](https://docs.live2d.com/en/cubism-editor-manual/standard-parameter-list/)

待机/视线/说话/表情是不同驱动来源，应约定覆盖与混合顺序。多个动作同时写同一参数时由开发实现冲突策略；画师交出多个文件不代表混合已自动正确。

## 3. 给画师与绑定师的需求单

以下字段可直接填写后用于沟通；空白项是待决定，不是要求供应方自行猜测。

| 类别 | 需填内容 | 验收方式 |
| --- | --- | --- |
| 使用场景 | 二次元桌面常驻；展开聊天/语音；是否需直播或录屏 | 在同一桌面背景与窗口占位上审图 |
| 身份与风格 | 明确成年角色；风格参考、服装、表情基调；禁止项 | 先审黑白轮廓/比例稿，再审色稿；不直接套用示例人物 |
| 视觉配比 | 总高H、头高h，头身比R=H/h；半身/全身；头宽/肩宽与手势可见区 | 画师标比例草图；绑定师检查目标变形是否留够绘制范围 |
| 屏幕占比 | 常驻与展开两档窗口占位、角色显示高度、脸部像素高度 | 同一素材两档展示，判断五官/表情能否辨认；不是拿原画像素直接当窗口大小 |
| 画布与色彩 | 画布尺寸、透明边界、RGB/8bit、sRGB；保留源工程 | 数值与配置可检查，缩小后的边缘/五官仍可读 |
| 可动范围 | 转头、俯仰、眼球、眨眼、张口、呼吸、头发/配饰等逐项选择 | 极值姿态检查遮挡、缺口、拉伸、穿帮 |
| 表情/动作 | 列实际需要的事件、持续/循环、淡入淡出、复位行为 | 每项独立预览，恢复中性姿态，停止不会卡在旧状态 |
| 纹理与渲染 | 目标图集配置、允许效果、目标renderer版本 | 本项目实际加载与资源测试，不能只凭Editor预览 |
| 修改范围 | 草图/色稿/绑定各阶段修改轮次、超范围改动报价方式 | 每阶段签收后冻结该部分，变更有记录 |
| 权利范围 | 自用、公开直播、录屏、商业使用、修改、跨软件使用、运行包备份/分享分别约定 | 阅读书面许可；保留作者/版本与授权文件 |

为做可比研究，可先用两个候选显示尺寸测试；具体数值由目标设备决定。若采用160/320 CSS px作为早期样张高度，只是项目试验起点，不能当行业交付标准或物理像素保证。

头身比是画风选择；屏幕占比是产品布局选择；原画/纹理分辨率是资产与渲染选择。三个量分别记录。不能把“4K素材”当作小尺寸可读或低资源占用的保证。

## 4. 拆件与绑定协作

画师、拆件人员、绑定师可以是同一人，也可以分别承担。先由绑定师根据目标动作检查分层草案，再让画师完成高成本上色，减少完成原画后重拆返工。

| 交接 | 项目建议的检查点 | 负责人 |
| --- | --- | --- |
| 草图→分层规划 | 正面/角度需求、脸/眼/嘴/头发/身体可动范围、覆盖区域 | 画师+绑定师共同确认 |
| 原画→拆件 | 可动部分独立；绘制原来被遮住的范围；命名清晰 | 原画/拆件人员 |
| 拆件→Cubism | 制作源PSD保留可编辑结构；另给可导入PSD | 拆件人员+绑定师 |
| 绑定→动作 | 参数ID、范围、默认值、所属能力与动作覆盖关系 | 绑定师 |
| 动作→应用 | 模型入口、相对路径、动作/表情名、可选设置和版本矩阵 | 绑定师+开发 |
| 应用→返修 | 以确定姿态、事件、输入音频与日志复现问题 | 开发+用户验收者 |

官方教程对眼、嘴、头发、身体的分离是示例做法；具体层数由画风与动作决定。不要要求所有角色必须达到某个总层数，或以层数代替质量。[拆件教程](https://docs.live2d.com/en/cubism-editor-tutorials/psd/)

## 5. 两份交付，不把制作源文件混入运行包

**制作档案**（用于修改，按合同约定是否交付）：原画源文件、拆件PSD与导入PSD、`.cmo3`、需要返修时的`.can3`、参数/动作清单、版本记录和授权文件。源文件取得权与运行使用权分别约定。

**用户运行包**（用于应用导入）：模型入口、`.moc3`、纹理以及入口实际引用的表情、动作、物理/姿势等文件，附预览图、作者/授权/导出版本说明。保持文件夹结构；不附Editor安装器、可执行脚本或未获授权的字体/配音。

应用自己的角色描述、声音选择与状态映射可由导入向导建立。角色图像许可不自动包含配音声线许可；角色人设、声音与长期记忆也不因导入模型就自动授权合并。

`.model3.json`一般作为资源引用入口，但不能据扩展名假设文件安全。导入器还需检查路径、大小/数量、解码后的纹理尺寸、模型完整性和不支持的特性；这些属于开发验收，不应转嫁给普通上传者手写修复。

## 6. 验收基准与数据

下列均为计划，执行数为0。建议至少覆盖不同作者或独立制作来源的素材，而非只让自己的样例通过；合法素材取得后才运行测试。

| ID | 检查 | 数据与判定 | 责任 |
| --- | --- | --- | --- |
| ART-01 | 原画/运行一致 | 同一中性姿态对照色彩、透明边缘、裁切；问题逐项签收 | 画师+用户 |
| ART-02 | 可动范围 | 全部约定参数极值与组合姿态；破图/露白/离屏均记录 | 绑定师 |
| ART-03 | 自助映射 | 由非制作者完成导入→预览→映射→保存→重开 | 开发+验收者；成功率=完成用户数/测试用户数，门槛待试验 |
| ART-04 | 音频/口型 | 已播放样本、停止、取消、切换角色；口型/音频不复活 | 开发；分别记录时间与不一致次数 |
| ART-05 | 缺件/旧版本 | 对缺纹理、损坏moc、无动作、未知参数、不支持版本明确报错或降级；不破坏原角色 | 开发 |
| ART-06 | 热切换与回退 | 反复导入/切换/撤销；旧角色释放、旧音频不重播、私聊不错误迁移，回退可用 | 开发 |
| ART-07 | 性能 | 同机同窗口与后端，逐项开角色/动作/效果；测CPU/GPU/RSS/显存、帧时间、纹理和mask，门槛待基线 | 开发 |
| ART-08 | 权利与版本 | 运行包与制作档案分别核对；授权范围、来源、版本与依赖可追溯 | 项目负责人/专业确认 |

图集尺寸与mask/混合模式都会影响渲染。官方图集文档展示4096等配置，但并未据此要求本项目一律采用4096。新特性还有SDK支持与负载差异，须用选定renderer实测。[纹理图集](https://docs.live2d.com/en/cubism-editor-manual/texture-atlas-edit/)、[SDK模型性能](https://docs.live2d.com/en/cubism-editor-manual/performance/)

## 7. 工种工作量与预算“配比”

不虚构“画师/绑定/程序各占多少”的统一百分比。先把交付工作分成互不重复的WBS，再以同一需求单取得估算。

| 工作包 | 交付/估算基础 | 前置 | 成本驱动 |
| --- | --- | --- | --- |
| A 角色设计与比例稿 | 草图、轮廓、半身/全身方案和修改范围 | 目标显示场景 | 设计原创程度、服装/手势、审稿次数 |
| B 原画与拆件 | 源文件、补全和可导入PSD | A签收、绑定师拆分审核 | 部件复杂度、细节、遮挡补画 |
| C 绑定与基础动作 | 参数、网格、物理、口型与极值验收 | B完成 | 角度、自由度、配饰、特殊效果 |
| D 表情/动画 | 实际事件清单与混合/复位规则 | C基础稳定 | 数量、复杂程度、循环与过渡 |
| E 应用适配与质量 | 导入、映射、版本兼容、资源和异常测试 | 运行包样例 | 格式差异、设备范围、缺件/升级处理 |

按角色记录工时区间`H_i=[L_i,U_i]`及报价`Q_i`。工时占比为`H_i/ΣH`，报价占比为`Q_i/ΣQ`，两者分开；区间数据应用明确的低/中/高场景计算，不能把区间端点随意混算成精确百分比。若一位供应方同时完成B/C，要求按交付范围去重，避免重复计费。

另列Editor/SDK、模型资产许可、配音、目标设备、存储与维护成本；均未知，尚未核实价格。动态角度/表情增多、换装或重新拆件会改变工作量，不按贴图文件数简单估价。增加多个可导入角色时，应用一次性适配成本与每角色制作成本分别计算。

## 8. 发布与许可：必须保留的门槛

Live2D官方许可页明确，正式发布中的“Expandable Applications”有专门审核/出版许可；通常个人或小规模业务豁免排除此类。允许用户扩展角色的应用**可能**适用，需要由Live2D确认，不能自行判断开源/个人就无费用。开发阶段与正式发布的要求不同，本轮没有联系厂商或签约。[官方SDK许可](https://www.live2d.com/en/sdk/license/)

资产作者的授权与SDK许可独立。购买一份角色，不自动取得公开再分发、云端角色市场、AI训练、声音克隆或跨软件修改权。正式需求单需分别约定允许用途、作者署名、改动、运行包备份/迁移与源文件取得。对不明确的条款保留专业确认，不将导入时勾选框当作权利已验证。

VRM若后续支持，还需单独研究0.x/1.0。本轮[VRM1.0 meta英文页](https://vrm.dev/en/vrm1/meta/)仅为TODO占位，未核验完整1.0字段；不能把旧版meta直接当1.0实现依据。

## 9. 事实、建议与未知

- **已核实事实**：文中所列官方PSD条件、拆件/导出/参数与目标版本行为、SDK发布许可条款存在；查阅日期2026-11-12。
- **可信待验证**：按选定SDK与导出矩阵能得到可运行模型；本项目未导入任何新Live2D资产。
- **项目建议**：能力分级、两份交付、向导生成映射、比例样张与WBS核价方法；不是官方统一标准。
- **未知**：用户具体画风/头身比/资产预算、供应方报价、目标设备、最终renderer与SDK、许可分类/费用及实际导入体验。

本轮只完成研究规格。实际踩坑：猜测的`texture-atlas/`与兼容页URL不可读，已沿官方目录定位到`texture-atlas-edit/`与`compatibility-with-cubism-5-3/`；5.3兼容文章仍含beta描述，不能当作所有最新版本的完整承诺。交接由主Agent统一更新。
