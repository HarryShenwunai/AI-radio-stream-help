# 自助角色导入：现有产品与格式证据

查阅：2026-11-12，Europe/London。用户目标是二次元桌面陪伴，用户可自行导入、配置和替换角色，不能把示例角色数量当作产品能力边界。本轮只读官方资料，没有运行或导入这些产品，也没有修改应用UI、购买、登录、提交或推送。

原先链接的`ui-references-2026.html`在当前工作区缺失；本轮复用已有产品/桌面研究并访问官方来源，未称读过缺失页面。

## 核心结论

至少四类已存在的自助流程可借鉴：图片状态装配、Live2D完整运行包导入、导入后的参数映射、与本地导入分开的公开分享。推荐首版设计同时明确PNG轻量入口与Live2D运行包目标，按能力逐级增强；不承诺把任意单张图自动变为完整Live2D。

“自助”应按用户完成任务定义：不改源码、不请求开发者为特定角色写分支，能够导入、预览、修正映射、启用、替换、导出/删除。支持范围用格式和经过测试的版本说明，不以固定角色名字或角色数量白名单实现。以上是项目建议，尚未实现。

| 产品/资料 | 官方文档核实的输入与流程 | 借鉴与边界 |
| --- | --- | --- |

| [nizima LIVE：How to add Live2D models](https://docs.nizimalive.com/en/tutorials/how-to-add-live2d-model/)（页标11/06/2024，日期顺序未另核） | 模型列表→添加→选择`.model3.json`→预览/切换；需要嵌入用数据，缺图标时用NO IMAGE | 用明确入口替代改目录；图标缺失可降级，核心模型/贴图缺失不能伪装正常 |
| [veadotube mini 2.2手册](https://veado.tube/docs/usage/mini/) | 用户为状态槽导入图片；每状态最多四张，可用单图、开闭嘴两图或眼嘴四图。现手册保存/加载`.veado`，状态可有快捷键 | 低成本自助入口。图片菜单和角色文件菜单分开；单图仍可用，不等于已有精细口型绑定 |
| [AIRI 0.13.0官方手册](https://airi.moeru.ai/docs/en/docs/manual/tamagotchi/setup-and-use/)（2026-10-28） | Models的选择器提供Import；Live2D使用完整ZIP。文档还列VRM、Spine、MMD、Tachie格式；动画/表情可用性由包内资产决定 | 借鉴格式识别、能力发现与可选配置；不因此把所有格式列为本项目首版必做。手册称部分截图较旧，未运行当前版本 |
| [Open-LLM-VTuber Live2D指南](https://docs.llmvtuber.com/docs/user-guide/live2d/) | 模型放入目录，再配置`model_dict.json`和角色配置。文档称渲染库支持Cubism 3–5、不支持2；名称/路径/缩放必填，表情和触摸动作可选 | 是可复用配置结构的参考，但该流程仍需要编辑配置，不能直接宣称已满足无代码自助。版本支持是其文档声明，未做本项目兼容测试 |

[VTS Model Settings](https://github.com/DenchiSoft/VTubeStudio/wiki/VTS-Model-Settings)（2026-04-11）进一步说明可设置待机动作、参数范围与平滑。动画、表情、物理和输入同时写同一参数时会互相覆盖。本项目的AI音频驱动仍应以实际播放为准，不能直接照搬麦克风驱动。

[nizima LIVE口型文档](https://docs.nizimalive.com/en/tutorials/lip-sync/)也区分基本开合与手动参数关联，并有Mac条件说明。它证明参数适配需要独立步骤，不证明任意模型都具备音素口型。

## 制作源文件与用户运行包分开

[Live2D文件类型](https://docs.live2d.com/en/cubism-editor-manual/file-type-and-extension/)与[嵌入用导出](https://docs.live2d.com/en/cubism-editor-manual/export-moc3-motion3-files/)于2026-10-13更新，核实以下分工：

| 交付层 | 文件或内容 | 在本项目的角色 |
| --- | --- | --- |
| 美术源文件 | 分层PSD与对应拆件说明 | 画师与绑定师协作；不是最终运行入口 |
| 绑定/动作工程 | `.cmo3`、`.can3`等 | 用于修改和后续维护，不应默认公开分发 |
| Live2D运行基础 | `.model3.json`、`.moc3`及所引用贴图 | 用户导入器检查入口、依赖与目标版本 |
| 可选增强 | `.physics3.json`、`.motion3.json`、`.exp3.json`、参数说明 | 物理、动作、表情与可读参数名称按实际存在启用 |
| 应用角色配置 | 画面缩放、锚点、能力映射、角色设定、可选声音配置 | 本项目另定义，不能假设所有模型自带聊天人格或声音 |

导出时可选择目标SDK版本；文件后缀相同不表示各运行库兼容。具体SDK/Core版本与资产组合须锁定后实测。PSD源图不因导入运行包而自动完成拆件/绑定；Cubism工程文件也不等于嵌入运行文件。

## 缺件、映射与降级的项目建议

以下是工程推断，尚未执行：

1. 图片入口允许单张透明角色图成为静态角色；可选开闭嘴/眨眼状态按槽装配。缺状态时保留静态显示，不捏造已有精细表情。
2. Live2D导入先验证入口和引用资产；缺核心文件、缺贴图或不支持版本时拒绝启用，保留旧角色并给出具体报告。
3. 可选表情、动作、物理缺失时仅停用对应能力。不要把无表情文件判定整个合法模型无效，也不要让不存在的选项看起来可用。
4. 标准参数给自动映射建议；非标准ID/范围可由用户在预览中校正。映射绑定到资产版本，不把上一模型的参数编号套给新模型。
5. 角色图片、人格卡、声音、私人会话数据分开存储。换外观与新建角色身份要有不同操作；导入模型不会自动授权共享原角色记忆。
6. 角色包只含允许的数据与资产，不执行包内脚本或模型文本提议的工具。导入校验与资源预算属于程序职责，不转嫁给画师口头保证。

## 本地导入与公开上传是两种操作

[VTube Studio Workshop规则](https://github.com/DenchiSoft/VTubeStudio/wiki/Workshop)将Steam分享作为独立流程，上传前展示文件列表，并警告PSD/CMO3源文件；创作者授权与本地能加载是不同条件。

本项目暂按“用户向自己的应用导入”设计。若用户还要在线分享或跨设备云同步，应另估鉴权、存储、版本、删除和授权范围。默认本机私有；不把模型、画师源稿、API凭证和私人记忆一起公开。

[AIRI当前配置说明](https://airi.moeru.ai/docs/en/docs/manual/config/)说会忽略VTS的`items_pinned_to_model.json`导入元数据。旧翻译资料仍有需手动删除的说法，不能跨版本混用；其手册另把模型云同步列为当前不可用。用户自助导入不应依赖一个未验证的云市场。

## 用于后续基准的样本维度

建议按能力覆盖选择互相独立的合法样本，而不是预装几个后宣称支持所有角色：

| 样本 | 要验证的独立假设 | 计划结果口径 |
| --- | --- | --- |
| 单图与同尺寸四状态图片 | 零绑定用户能自助启用 | 不改JSON/源码，静态可用；可选状态正确切换 |
| 标准参数Live2D完整包 | 自动识别基本行为 | 基础加载、嘴/眼映射、缩放锚点有明确预览 |
| 非标准参数、不同目录名、中文路径 | 不是按演示角色写死 | 引用可解析，用户能改映射，版本信息保留 |
| 无表情/无物理的合法模型 | 增强缺件能降级 | 仍能基础显示；不可用能力明确 |
| 错版本/缺贴图/损坏包 | 失败可恢复 | 不覆盖当前角色，报告定位具体原因 |
| 新旧角色切换、更新与回退 | 资产与状态不会串联 | 旧generation声音/动作失效；会话归属明确 |

目前上述导入/兼容基准测试执行数为0。现有应用的115项回归不能替代这组角色导入测试。成功率、耗时与资源门槛需用目标设备和实际样本确定；不编造测试通过率或价格。

## 证据分层与未知

- 已核实事实：本轮确实访问并读到上述官方流程、文件类型和参数说明；并非运行效果已核实。
- 可信待验证：这些产品在选定版本上的实际导入、兼容和自动映射表现。
- 工程推断：以图片入口+Live2D运行包形成分层能力，使用独立样本证明自助而非固定角色特判。
- 未知：本项目最终渲染库/SDK、商用和分发许可、画师及绑定报价、目标硬件、实际性能、用户是否需要云同步/公开分享。

本轮没有核实当前价格，不写“免费商用”或虚构费用。来源的产品能力不等于许可授权。本轮也没有视觉截图评审、下载模型、运行Cubism或安装商业应用。
