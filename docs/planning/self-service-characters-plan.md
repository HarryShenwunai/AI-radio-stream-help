产品目标是用户自行导入、配置和更换合法角色。预装样例只用于验证，不限定可用角色。桌面陪伴继续采用角落常驻、按需展开的方向。

推荐先建立通用角色与资产边界，用PNG完成自助导入流程，再接版本固定的Live2D运行包。Live2D是正式目标；图片阶段不等于动态角色需求完成。本轮交付研究、基准和计划，尚未实现导入或修改UI。

## A 执行摘要、现状与决策

目标用户包括已有角色立绘/模型的使用者，以及需要与画师、拆件和绑定人员合作的人。核心场景是导入自己的角色，在桌面交流，换外观或新增独立角色，并能失败恢复和自行删除。

核心成功结果：用户自行完成导入、预览、映射、启用、更新和回退。过程中不改源码、不编辑配置文件、不等专用版本。支持范围按格式、版本与能力声明，不按角色名字写白名单。

当前最重要的决策是支持顺序、Live2D发布许可、目标OS与资源基线。“上传”暂按导入自己的应用理解；公开角色市场、云同步另立范围。

| 证据类别 | 已知内容 |
| --- | --- |
| 已核实本地事实 | 现有HTTP/SQLite、文字/语音、generation与晚到拒绝可复用；当前只有一套角色设置、聊天和记忆，尚无角色隔离字段 |
| 已核实文档事实 | VTube Studio、nizima LIVE、veadotube mini、AIRI有明确导入流程；Cubism区分制作工程与运行导出 |
| 可信待运行验证 | 上述产品的自动映射、兼容范围与降级行为；本轮未运行导入或登录产品 |
| 工程推断 | 通用资产登记和分级能力比固定角色分支适合此目标；先PNG流程可减少SDK许可对首批验证的阻塞 |
| 未知 | 用户OS/GPU、画师与绑定报价、最终SDK/宿主、许可分类费用、是否需要云端共享 |

现有115项Python、8项Node与12项Chrome记录属于前一批运行代码。它们没有覆盖本次导入功能；新增28项候选验收均NOT_RUN，夹具准备数0。

不做的内容：本轮不改应用UI、不采购或委托画师、不登录或发布。首版不承诺PSD自动绑定、任意格式兼容、自动声音克隆、公开角色市场或导入包执行插件。

区间是工程拆解，按8小时/人日，不是报价或承诺。两方案均保留现有后端。外接现成渲染器可作后续对照，接口、许可和桌面体验尚未验证，不当作已成熟替代。

推荐A的完整目标必须包括PNG单图自助和常见Cubism运行包。另需依赖检查、预览/映射与版本报告。角色/外观分层、取消/回退和单音频拥有者也是必做项。B是首版格式收窄方案，采用前须另确认这项范围取舍。Live2D正式发布须完成适用许可确认。

应该做：可选状态图、标准参数建议、非标准范围校准、可编辑锚点/缩放、重复导入与资产更新、明确缺项降级。

可以延后：VRM、Spine、MMD、多人同屏、云同步/市场、自动生成/拆件/绑定。优先让声明支持的格式真正自助可用。

## C 导入流程、架构与权限

建议流程：选择文件 → 隔离暂存/预检 → 离线预览 → 映射与用户确认 → 原子启用。失败保留当前角色；更新生成新修订，支持退回上一可用版本。

| 层 | 数据与责任 |
| --- | --- |
| 资产包/修订 | PNG状态或Live2D入口、依赖、hash、来源、版本、实际发现的能力 |
| 角色身份 | 用户配置的人格、称呼、声音选择、主动联系策略；与外观分开 |
| 关系与会话 | 按角色身份隔离聊天、记忆、约定与遗忘账本；共享需明确选择 |
| 映射配置 | 资产修订对应的眼/嘴/动作/锚点与范围；向导生成，不要求画师手写专用JSON |
| 输出归属 | 角色身份、资产修订、会话与generation共同决定文字、声音、动作是否仍有效 |

同一角色换外观保留该身份的关系数据；新增独立角色默认隔离。操作前停止旧声音/动作，取消迟到结果，再激活新资产。当前数据库需迁移，不能只增加上传按钮。

运行包以model3.json及其引用为入口，实际加载moc3和纹理。可选表情、物理、动作缺失时停用对应能力；核心资源损坏或版本不支持则拒绝启用。标准参数只作建议，非标准ID和范围由预览校准。

[官方运行导出说明](https://docs.live2d.com/en/cubism-editor-manual/export-moc3-motion3-files/)与[SDK模型加载](https://docs.live2d.com/en/cubism-sdk-manual/model-web/)支持上述资源关系；应用自己的导入向导尚未实现。

边界是数据包：不执行脚本，不依包名授予权限，不跟随外链，不接受包内凭证或工具授权。图片/模型元数据不自动写入聊天提示。人格导入如后续支持，也需单独预览确认，不能改变系统权限与渠道边界。

解压前和过程中检查路径、重复条目、链接与资源量；解码后再检查像素、纹理、模型复杂度。不能只看ZIP体积。预览与当前角色并存的内存峰值必须计入；低资源设备允许终止候选并恢复旧资源。

本地文件由本人选择，启用由本人确认。首次云同步、公开分享、向外发包、购买素材和厂商询问不由Agent自动执行。导入日志记录ID、阶段、版本、耗时和错误码，避免记录私聊、密钥或未必要的源文件内容。

## D 给画师与绑定师的基准和配比

把“配比”分为视觉比例、资产/能力配套和工种预算三部分。用户尚未指定具体画风与头身比，下面给可填写和可测的方法。

| 项目 | 定义/基准 | 谁确认 |
| --- | --- | --- |
| 头身比 | R=角色总高/头高；由比例稿标注，按画风比较 | 用户+画师，绑定师检查可动范围 |
| 屏幕占比 | 角色显示高/目标桌面可用高；脸部显示像素另记 | 用户+桌面开发；同背景审小尺寸 |
| 初始样张 | 同一占位下半身/全身、静态/轻动效对照；可探索160/320 CSS px两档 | 项目试验点，非行业强制值或最终规格 |
| 原画/图集 | 源画布与运行纹理分别记录，不把4K当作质量承诺 | 画师+绑定师+渲染开发 |
| 动作/能力 | 基础显示、眼口、表情、待机逐项声明；缺可选项可降级 | 绑定师交清单，开发发现并映射 |

Cubism制作导入PSD需符合其RGB/8bit等条件；可动部件需要分离并补全遮挡区域。头身比、总层数、统一4K尺寸或固定动作数没有本轮可核实的通用强制标准。[PSD要求](https://docs.live2d.com/en/cubism-editor-manual/precautions-for-psd-data/) · [官方拆件教程](https://docs.live2d.com/en/cubism-editor-tutorials/psd/)

| 制作交接 | 交付物 | 验收与返工门 |
| --- | --- | --- |
| 需求→草图 | 明确成年角色、风格参考、半身/全身、窗口占位与权利范围 | 用户先审轮廓/比例；尚未确定具体角色 |
| 草图→分层 | 可动范围、拆件草案、遮挡补画计划 | 绑定师在精绘前复核，减少重拆 |
| 原画→绑定 | 可编辑源稿与可导入PSD分别保存 | 图层/色彩/极值可动范围按约定检查 |
| 绑定→应用 | 参数ID/范围/默认值、版本、动作/表情清单与运行包 | 由非制作者导入并预览，记录破图/口型/复位问题 |
| 应用→返修 | 同一姿态/音频/事件与日志 | 修改轮次和超范围报价提前约定 |

两份交付分开：制作档案为PSD、cmo3、必要的can3及说明，是否交付依合同；用户运行包为入口、moc3、纹理及实际引用的增强文件。运行使用权、源文件取得、改动、跨软件使用、直播与再分发分别约定。

预算配比按交付WBS核算：设计、原画/拆件、绑定、表情动作、应用适配与QA分别记录工时和报价。工时占比=该项工时/总工时；报价占比=该项报价/总报价。费率/单价未知，不填固定百分比；同一人兼任工种时去重。

具体可填写需求单、制作验收与报价字段见[画师交付基准](../research/artist-rigger-brief-2026-11-12.md)及[报价模板](artist-quote-template.csv)。无需为每个用户先委托一整套模型，已有合法运行包也应能自助导入。

## E 基准样本、指标与验收

候选分级为C0静态PNG、C1状态图、C2基础Live2D、C3非标准参数/增强、C4未来其他格式。每条拟发布的格式路径至少两套独立结构，其中一套实现冻结后加入作为保留样本。该最低抽样用于发现演示角色特判，不证明已泛化到所有模型。

基础结构夹具可自造；真实Live2D样本需先核对用途与许可。官方样例“可下载”不自动等于可用于AI、修改或再分发。正式样本索引保留版本、hash与授权范围，当前样本未获取。

| 需求 | 指标/数据与目标依据 | 验证与时点 |
| --- | --- | --- |
| CR-01 自助导入 | 无开发介入启用的有效包数/该格式有效包数；发布支持流程源码改动0 | CI-01–06；U1/U3/U4和用户验收 |
| CR-02 版本/缺件 | 实际通过组合/已测声明组合；关键失败准确拒绝、可选项准确降级 | CI-07–10；U4/U6；未知组合不宣称通过 |
| CR-03 参数校准 | 标准建议与非标准范围均可在应用内预览/修正 | CI-02/05/10；U3/U4；人工任务记录 |
| CR-04 导入边界 | 由包引用引发的越界访问、脚本执行、外链请求及越权副作用0 | CI-11–16/28；U1/U6；安全关键项全部满足 |
| CR-05 事务恢复 | 取消/崩溃/磁盘不足后半安装激活0；旧版本可用 | CI-17–19；U1/U6 |
| CR-06 身份与媒体 | 默认隔离时canary串用0，切换后旧声音/动作生效0 | CI-20–22/28；U2/U5/U6 |
| CR-07 删除与遗忘 | 按选择保留/删除关系数据，旧备份不复活已遗忘事实 | CI-23/24；U2/U6 |
| CR-08 桌面可用性 | 小尺寸识别、误触、焦点与停止任务可观察；阈值待用户基线 | CI-25；U5/U6 |
| CR-09 性能回收 | 导入/切换p50/p95、全进程树CPU/GPU/RSS/显存、帧时间与回收趋势 | CI-14–16/26；U0定候选预算，样例后冻结阈值再U6验收 |
| CR-10 来源与交付 | 运行包/源文件分离、版本和用途可追溯；声明不等于真实授权 | CI-27、ART系列；U0/U6与专业确认 |

全部新增28项测试尚未执行。完整规格见[基准设计](../research/character-import-benchmark-2026-11-12.md)与[机器可读清单](../../review/character-import-test-specs.json)。用户完成率、时延、资源阈值待目标设备和首轮任务基线；不得把无法执行项从结果中隐藏。

RGBA8单层像素缓冲可按Σ(宽×高×4)估算。实际峰值还包含解码副本、mipmap、渲染器、掩码与新旧角色并存，须实测。切换不额外常驻第二份LLM；单个音频拥有者负责声音和口型状态。

## F 工作包、依赖与估算

角色是所需职责，不代表已聘用画师。主Agent统筹；后端、图形/桌面、QA可由协作Agent分工，用户参加素材与体验验收，专业许可确认单列。

| 包 | 负责人/依赖 | 交付物 | 人日区间 | 验收 |
| --- | --- | --- | --- | --- |
| U0 支持与许可边界 | 主Agent+QA；设备/范围输入 | 固定版本矩阵、许可待确认清单、资源测量方案和样本登记 | 1–2 | 格式/能力/费用未知明确，不据开源标签推许可 |
| U1 通用导入事务 | 后端；U0 | 隔离暂存、依赖/预算检查、资产修订、启用回退 | 2–3 | 关键坏包、取消、失败不改当前版本 |
| U2 身份与数据迁移 | 后端+独立QA；U0，与U1对齐 | 资产/人格分层、备份迁移、关系/遗忘隔离与切换语义 | 2–4 | CR-06/07；迁移失败可回退 |
| U3 PNG/状态映射 | 图形/前端；U1/U2 | 单图与可选状态槽、自助预览/锚点/映射 | 1–2 | 新名称/路径/保留样本可用，单图降级正确 |
| U4 Live2D适配 | 图形开发+绑定师；U0许可边界/U1/U2 | 固定运行库、完整包加载、参数范围与能力发现 | 4–7 | 两个独立结构通过，不靠角色名；发布前许可另过门 |
| U5 桌面生命周期 | 桌面/媒体开发；U0宿主选择/U2/U3或U4 | 常驻/展开/隐藏、穿透焦点、单播放拥有者与旧动作失效 | 3–5 | 目标OS验证焦点/声音/口型/恢复 |
| U6 基准与用户验收 | QA+用户+独立审查；U1–U5相应里程碑 | 兼容矩阵、用户任务、故障/资源报告、回退演练 | 3–5 | 声明范围与实际结果一致，关键失败阻断 |

A路线基础16–28人日，加3–5储备为 **19–33人日（152–264小时）**。PNG自助桌面里程碑不含U4：基础12–21，加2–3储备为 **14–24人日**；以后增Live2D及追加储备，总量回到A区间，不能重复加一次U6。

B路线首版不含U3：基础15–26，加3–5储备为 **18–31人日**。后补图片能力需另列回归差异，不假定免费。

按一名熟悉现有代码的开发者、8小时/人日估算。区间只覆盖一个选定OS，第二/第三OS另估。素材差异与SDK约束影响区间；厂商审核、画师排期、购买、模型制作、VRM、微信与真实直播另估。

这份是自助角色桌面范围，不等于全项目剩余总量。与旧18–33人日方案的界面、生命周期、QA有交叠；U0须合并剩余工作，避免简单相加或按Agent数量除工期。

## G 预算、资源与风险

一次性成本分为应用开发、每个新角色的可选制作、SDK/素材许可与设备。用户已有合法运行包时，无须重复支付制作费用。持续成本包括维护兼容、模型/语音调用和可选云服务；默认本机导入不新增云存储承诺。

开发预算=实际工时×约定费率。角色预算=设计+原画/拆件+绑定+表情动作+约定修改。画师、素材、配音和云费用未取得报价。SDK官方有公开价目，但本项目适用类别与费用待确认；不把价目直接当项目报价。

敏感性：角色数量主要增加资产存储和每角色校准；同时显示数量增加渲染与纹理资源。动作、可动角度、换装复杂度和返修改变制作工时；文本/音频常开改变推理费用。一次性通用导入开发与每角色成本分别记录。
