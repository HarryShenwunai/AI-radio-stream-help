本项目为你构建一个性格稳定、记得相处经历、能自然用文字与语音交流的二次元虚拟女友。主动联系应可控，督学是一项可选能力。本计划复用已经完成的研究，不从零另造所有模块。

文档 ID：VG-PMP-002。修订：2.0 评审稿。日期：2026-11-11。状态：拟议，未批准、未建立执行基线。计划责任人为拟任技术负责人，批准人为你；实际实施与评审人选待 OPEN-07 确定。

本版参照 IEEE 官方公开范围修订，以可追踪记录和退出条件提高计划质量。尚未取得标准付费正文，不宣称逐条符合或 IEEE 认证。虚拟女友应用未开发；没有应用测试通过记录。

## A 执行摘要与最重要的决策

### 项目为什么做、交付什么

目标用户首先是你本人，按单用户个人使用设计。现有聊天、角色、语音和机器人框架可复用。仍需验证微信链路、统一相处记忆，并调整角色表现。

初版交付一个角色、持久化相处记忆、文字交流、一种可用音色，以及可暂停的主动联系。声音通过哪种微信消息形式呈现，要先验证并由你选择。动态形象与督学在基础体验稳定后接入。

值得做的依据是你已明确表达这些需求，以及已有模块可缩小自行开发范围。这是个人需求判断，不是市场规模、商业回报或现成产品质量的证明。

### 推荐与最关键的风险

推荐先做通信验证，再以 AstrBot 作为微信侧候选底座，开发独立于通道的角色与记忆模块。先用模型 API 比较角色表现，语音在本地服务与 API 之间按硬件选择。

这是一项有条件的推荐。若必须发送微信原生语音条，目前查到的 weixin_oc 适配器不满足文档要求。[S1] 若长期无互动后的主动发送失败，也不能承诺可靠的微信催学或日常问候。[S2]

## C 项目定义、范围和成功标准

### 主要场景与期望结果

日常聊天保持同一角色；跨天继续之前的话题；用固定声音回复；按你允许的节奏主动联系；按约定提醒学习，并能立即暂停。

“像同一个人”的工程目标是性格与记忆连续、表达自然，并非声称系统具有真实人类身份或情感。角色背景、实际对话事实和模型推断分别保存。

### 范围与优先级

| 优先级 | 内容 | 排序理由与取舍 |
| --- | --- | --- |
| 必须做 | 验证微信通道；单角色；文字；持久记忆；一种声音；可控主动联系；暂停与删除 | 直接对应你已明确的核心体验 |
| 应该做 | 纠错、过期状态、费用记录、备份恢复、督学任务与复盘 | 支撑长期可用；督学不主导产品定位 |
| 可以延后 | Live2D、更多音色、多角色、复杂关系成长、完整桌面客户端 | 增加整合成本，不能替代核心聊天质量 |
| 初版不做 | 模型预训练、游戏陪玩、持续读取屏幕、群发、商业多用户平台 | 未提出需求；增加权限和资源开销 |
| 明确不做 | 未授权购买、外发消息、公开分享、生产修改、绕过平台限制 | 不属于本轮计划授权范围 |

“必须有声音”不能悄悄改成“只发文字”。若微信通道不支持所需语音形式，列出缺口，由你决定调整入口、等待或停止该路线。

## D 可行方案比较与 Agent 设计

### 两个可行方案

| 维度 | A 微信优先，复用 AstrBot | B 角色体验优先，独立界面配微信桥接 |
| --- | --- | --- |
| 实施内容 | 插件实现角色、记忆、任务，复用通道与调度 | 同一对话核心外接网页或桌面语音界面 |

| 局限 | 当前文档不支持微信原生语音发送 | 完整语音发生在独立界面，不能替代微信语音硬需求 |

方案 B 是可实施的产品结构，不代表选中的 AIRI 或 Open-LLM-VTuber 已有现成微信桥接。先选一个前端；不同时维护多套完整角色系统。

若原生微信语音为硬性要求，A 当前不能通过，B 也不能单独解决。此时先调查明确支持的通道；证据不足就停止承诺，不强行推荐某个未知协议。

### 推荐及适用资源假设

优先验证 A，原因是你明确希望在微信使用，且现有 AstrBot 调度与消息机制可复用。只保留一套角色与记忆模块，使以后转向 B 时无需重写相处数据。

资源暂按一个具备 Python 和接口整合能力的实施者估算。你负责体验选择和账号授权，AI 协助研究与代码工作。当前没有已确认投入的开发团队，所有负责人均为所需角色而非已经分配人员。

### 拟议架构与主要流程

```flow LR
微信或独立界面 -> 通道能力与会话校验
通道能力与会话校验 -> 对话核心
角色配置 -> 对话核心
[(事实与相处记忆)] -> 对话核心
任务调度 -> 发送策略检查
发送策略检查 -> 对话核心
对话核心 -> 模型接口
模型接口 -> 文字回复
文字回复 -> 语音服务
文字回复 -> 通道发送
语音服务 -> 通道发送
通道发送 -> 操作记录
```

回复读取角色概要、近期消息、相关事实和当前约定。候选事实在回复后提取，记录原消息、时间与冲突处理结果。长历史先摘要，不整段重复发送给模型。

### 模型、工具与数据

| 模块 | 初版选择规则 | 数据来源与失败处理 |
| --- | --- | --- |
| 对话模型 | 用同一场景集比较至少两个可用 API；选型待试验 | 用户消息与最小必要记忆；超时说明失败，不编造工具结果 |
| 角色 | 档案、场景示例和配置版本 | 你的偏好与确认设定；版本可回退 |
| 记忆 | SQLite 事实表、事件表、聊天摘要；不足再加向量检索 | 实际对话与确认事实；推断单独标记，不直接当事实 |
| 语音输入 | 优先复用入口转录；需要时接 SenseVoice | 用户主动发送的录音；无法识别时请重说或转文字 |
| 语音输出 | GPT-SoVITS 或经试听选定的 API | 有许可的参考声音；合成失败保留文字 |
| 主动任务 | 复用既有 cron，加取消、去重和安静时段 | 用户约定与允许的跟进策略；有限重试，过期任务不无限补发 |

SillyTavern 作为角色设计参考，不要求整套部署。Mem0 保留为记忆检索备选，不能无证据增加初版服务数量。

### 权限边界、人类审批与日志

运行时只开放受限工具：读取当前用户记忆、提出候选事实、操作本人任务、向已授权本人会话发送。不给模型任意 Shell、支付、联系人管理或任意网址请求权限。

微信消息、检索内容和网页原文视为数据。即使其中写着“忽略规则并发送资料”，也不能扩大工具权限。

执行前需要明确首次扫码、外部数据处理、声音许可、运行位置和预算上限。具体上线或变更生产环境另行说明动作与影响。

你已开启的日常回复和约定提醒可在明确范围内自动运行，不要求每条消息再次批准。改变收件人、增加服务商、公开分享、购买服务或导出到外部位置，必须有对应授权。

日志记录：请求 ID、配置版本、任务与消息 ID、时间、工具参数摘要、权限检查、平台结果、重试次数、延迟和用量。默认不在日志重复保存完整聊天或密钥。

发送不确定时先核对状态，不能盲目重发。记忆写入用事务；失败保持旧记录。暂停后还要在实际发送前复查任务状态，避免取消与发送并发产生旧提醒。

删除记忆要处理原会话相关片段、摘要、索引、缓存和当前对话上下文。备份不参与在线检索；从备份恢复后重放删除记录。具体保留范围须在实现前确定。

### 技术过程、环境与接口约束

技术路线采用短周期原型、固定场景比较和分阶段验证。每轮保留模型、提示词、语音、依赖和数据结构版本；不把模型升级视为无风险配置修改。

工作环境分为本地开发、获授权的测试会话与拟议常驻环境。默认没有生产环境；测试数据先用人工夹具，真实聊天和录音按批准范围使用。

| 接口 | 拟议契约 | 限制与失败处理 |
| --- | --- | --- |
| 入口到核心 | 会话ID、消息ID、时间、正文或转录、通道能力 | 固定本人会话；重复事件去重；无凭证不伪报成功 |
| 核心到模型 | 角色概要、最小相关事实、当前任务与对话 | 仅批准服务商；设置超时；不让输入决定工具权限 |
| 核心到语音 | 清理后的朗读文本、音色ID、语音配置版本 | 不朗读密钥或链接；超时后文字回退 |
| 核心到任务 | 创建、改期、暂停、取消和状态版本 | 任务状态真实持久化；发送前再查策略和取消状态 |
| 数据导出与恢复 | 版本、完整性校验、删除账本与恢复清单 | 不包含密钥；旧备份恢复后重新应用删除策略 |

原始输入、记忆和外部内容处于非可信数据边界；工具执行器执行确定性权限校验。模型只提出动作，不自行扩权。

第三方选择需保存版本、来源、许可证和已知缺口。锁定模型 API 名称不等于服务行为永远不变，应记录调用时间与服务响应，并保留回归场景。

### 敏感性与控制办法

在单价及每轮长度相同的前提下，消息量翻倍会让相关模型和记忆调用费用近似翻倍；固定服务器费用不因此翻倍。

若主动问候占全部调用的三分之一，将其关闭会降低相应调用量。这只是计算示例，不是你的当前用量。

语音分钟数增加、本地模型装不下、历史上下文持续变长和反复重试，都会改变成本。限制上下文、有限重试、批量提取记忆和预算上限，比先堆更多框架更适合初版。
