# 角色视觉质量目标

> 2026-11-13：当前 Live2D 已有独立技术实现，下文实现状态属于早期记录。本轮静态修正与同源分层检查见[母稿重组保真要求](../implementation/live2d-master-reconstruction.md)；Windows/4060 和用户画风仍待验收。

更新：2026-11-12。依据：用户本轮上传的参考图与“我想要的效果和质量是这样的”；设备自报“4060 32G”，按 RTX 4060 / 32GB 内存理解。设备型号尚未由程序探测，CPU、显存、驱动、屏幕分辨率与移动/桌面版本未知。这是新的验收方向，尚未实现或由用户验收。

## 已确定的方向

参考画面呈现自然的面部比例、细致发丝、柔和皮肤过渡、窗边逆光、低饱和配色和安静的表情。目标是细腻、自然的二次元角色表现。画面中的短发、衣服和杯子不是软件固定角色或必选素材。

用户仍可导入和替换自己的角色。默认素材只帮助首次启动，不能用几名预设角色代替自助能力。研究图不能作为已获得可分发模型、分层稿或动画的证据。

## 必须区分的三层

| 层 | 可观察结果 | 当前证据 |
| --- | --- | --- |
| 静态保真 | 用户导入的细节、边缘和比例在实际尺寸下清晰；有色彩差异时可先预览再启用 | PNG 真解码与原尺寸资源已实现；ICC 色域转换未实现，建议 sRGB8 |
| 动态表现 | 眨眼、视线、口型、转头自然连续；停止声音后动作及时收敛 | 当前仅有真实播放驱动 idle/talk 状态图；未达到本层 |
| 实时画质 | 实际模型在近景下保留材质、光照与表情，桌面小窗不干扰学习或游戏 | 需固定模型/渲染器与目标 Windows 设备实测 |

单张图只提供画面参考，不能证明其由 3D、Live2D、绘画或生成工具制作，也不能据此推导可动模型。上传一张图能保留静态画面；转头和表情需要相应的绑定、动画或其他可用驱动数据。

## 软件选择与验证顺序

继续复用角色目录、外观修订、预览启用、会话隔离、单音频拥有者和 Windows 宿主。现有 PNG 版本作为基础验证版本，不能作为目标视觉质量的最终成品。

| 路径 | 能控制的表现 | 限制与验证条件 |
| --- | --- | --- |
| 分层 2D / Live2D | 保留原画质感；在绑定范围内驱动表情、视线、头部 | 需要对应可用资产、固定 SDK 版本与可分发许可；灯光多由原画决定 |
| 3D / VRM 或受约束 glTF | 相机、实时光照、材质与骨骼表情 | 模型、纹理和毛发决定上限；普通 VRM 并不自动达到参考质感；需要 GPU 与资源预算 |

先用来源和使用范围明确的独立样本比较近景、桌面小尺寸、说话与静止，再决定首个动态格式。不因参考图看起来立体就直接判定必须使用 3D，也不把支持某种文件格式等同于达到画质目标。

渲染器需有清晰的加载、预览、启用、释放和 context-lost 回退边界；禁止上传包执行任意脚本或访问系统。导入失败保留当前外观，渲染失效回退可读的静态状态。

## 画质和性能一起验收

- 在同一合法资产、同一机位和同一输出尺寸下比较，不能用不同美术水平的样本替代渲染器比较。
- 检查眼睛、发丝、轮廓、透明边缘、口型与表情过渡；记录用户认可与否，不自评“100分”。
- 记录展开与小窗的帧时间 p50/p95、CPU/GPU、完整进程树内存/显存、连续运行稳定性和声音打断延迟。
- 隐藏时暂停渲染；小窗与展开使用不同渲染预算；画质档位可切换。当前 backgroundThrottling 不是省电验收证据。
- 以用户报告的 RTX 4060 / 32GB 内存为开发基准，优先验证3D材质/光照样例；这是工程选择，不是参考图制作方式或目标效果已达成的证据。
- 初始候选目标为小窗30fps、展开60fps，对应帧时间33.3ms/16.7ms；取值用于区分角落省资源与展开流畅两种场景，尚未冻结或实测。必须在固定合法样本、输出尺寸、DPI和模型推理并发条件下记录p50/p95，再决定正式门槛。
- 当前默认推理构建使用CPU版llama.cpp，尚未实现3D渲染或CUDA加速。不能因用户有独立显卡就声称本版本已启用这些能力。

Windows 构建准备继续推进；视觉目标的新增不把当前未验收的基础版本改称正式成品。
