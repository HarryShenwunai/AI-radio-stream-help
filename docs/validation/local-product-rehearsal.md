# 本地产品闭环开发验证

用户范围：停止安排平台环境测试，先完成本地开发。此修改在产品中提供“本地互动演练”，不需要账号或密钥，不建立网络接入线程。沿用已有生成、审核、语音、输出和停止逻辑，演练输入与输出标记local_rehearsal。

## P7方案及竞争解释

原问题：开发脚本能模拟，普通用户从产品入口不能完成同样的本地验收。检查确认不是模型或语音能力缺失，而是缺少受控的本地输入入口。最小改动：复用LiveIngress及现有输出状态机，增加仅本机所有者可使用的演练动作，不增加运行依赖、后台线程或轮询。

边界：主动开始；消息最多300字符、队列保持原有200条上限；30秒原消息期限不变；未确认不生成/不播放；结束与重新开始取消旧任务和输出令牌，重开不带入旧材料、话题或消息；私人历史不加入公开上下文。演练输入不构成工具或公开发送授权。

## 失败与区分实验

1. 开发发现submit返回字符串。错误布尔判断会把invalid当成功；固定输入空消息，已知坏判断返回accepted=true，修复后拒绝。结果见negative-control.json。
2. 初版测试使用单元HTTP夹具10秒超时，真实模型第二次生成超时；改由实际浏览器按钮执行，未修改产品30秒期限。
3. 完整回归与真实模型同时执行时，生成24.58秒，语音4.94秒，加审核操作超过事件期限，输出被拒绝。仅改变运行调度，待回归结束后同一脚本单独执行：生成10.74/6.49秒，语音5.57/1.57秒，闭环通过。此证据支持测试负载影响，不能证明所有高负载场景已解决；负载下时效是仍需进一步界定的产品限制。
4. 首次完整质量报告每项检查通过，但源码稳定性检查拒绝：测试脚本在检查期间被修改。该报告保持failed；最终必须使用冻结源码重新执行的报告。

## 已执行

- tests/test_local_rehearsal.py：实际HTTP请求测试无后台接入、未确认不输出、无效输入拒绝、未授权403、重新开始清理、结束后拒绝输入。
- tests/local_product_browser.py：真实Chrome桌面1024/1280窗口、实际Qwen3-4B、实际Kokoro中文语音；本地入口→输入→审核→字幕/音频播放→停止→再次输入→完整播完→结束演练。停止单次观测118.4ms，非承诺上限。
- 原始输入、生成finish_reason、WAV、浏览器音频、双窗口未剪辑录像、Trace、失败状态均在证据包保留。录像本身无音轨，音频单独提供。
- 仅Linux PC开发验证；不代表Windows10/11、RTX4060、真实OpenAI、系统扬声器或独立内容质量通过。没有本次账号/平台环境验收。

## 复跑

```sh
PYTHONPATH=src:tests python3 -m unittest -v test_local_rehearsal
python3 scripts/quality_gate.py --bootstrap --full --report evidence/quality.json
# 等质量检查结束，再运行真实模型，避免测试资源干扰。
COMPANION_MODELS=/path/to/models COMPANION_VOICES=/path/to/voices PYTHONPATH=src:tests python3 tests/local_product_browser.py --chrome /path/to/chrome --out evidence/local
```

真实模型脚本需要llama-cpp-python0.3.36、kokoro-onnx0.6.1、misaki[zh]0.9.4、Playwright1.62.0及已授权模型文件。测试锁定seed42、4推理线程、上下文4096和批次256；当前测试机并非目标机器，依赖安装在隔离目录而非修改产品依赖。
