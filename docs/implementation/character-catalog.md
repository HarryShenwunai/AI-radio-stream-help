# 独立角色目录与数据库

实现日期：2026-11-12。`src/companion_runtime/characters.py`提供本机角色元数据目录；聊天生成、HTTP鉴权、播放器与资产验证由应用层负责。

## 数据边界

- `characters.sqlite3`只存角色UUID、显示名、创建时间、外观修订UUID、归档状态、当前角色指针及待清理删除记录。
- `profiles/<角色UUID>/companion.db`存该身份自己的设置、聊天、记忆、约定、审计与遗忘记录，继续使用现有应用的表结构。
- 原`api-key`保留在数据根目录，由应用作为全局提供方凭证管理。本模块不读取或复制密钥。
- 新建角色只创建空数据库文件，不复制其他身份的设置或私密关系记录。应用须在新身份上下文中调用已有初始化代码填表。

显示名不参与文件路径。UUID必须为标准小写形式；未知ID、链接或丢失数据库明确报错，不偷偷重建一个空私聊库。

## API

`CharacterStore(root: Path, max_profiles=50)`。默认50是初始工程限额；待清理删除占用也参与新建额度检查。

| 方法 | 结果/行为 |
| --- | --- |
| `bootstrap()` | 幂等创建初始角色，或返回已有当前角色；需要时迁移旧数据库 |
| `active()` / `get(id)` | 返回`id/name/created/avatar_revision/archived` |
| `list(include_archived=True)` | 列出元数据；归档身份可恢复 |
| `create(name)` | 创建独立空数据库，不自动选择该角色 |
| `select(id)` | 显式切换可用身份；不能选择已归档角色 |
| `rename(id,name)` | 更新目录显示名；应用负责同步该身份settings中的名称 |
| `validate_name(value)` | 写settings和目录前共同使用的1–80字名称校验；去首尾空格，拒控制字符和孤立代理码点 |
| `set_appearance(id,asset_id)` | 更新外观修订UUID；不改身份或私聊数据。允许None撤回外观；不验证资产文件是否存在 |
| `archive(id)` / `restore(id)` | 保留数据库，改变列表可见状态；不隐式切换当前角色 |
| `delete(id)` | 删除非当前身份；结果含`cleanup_pending`说明物理清理是否完成 |
| `cleanup_pending_deletions()` | 重试受控trash清理，返回cleaned/pending计数 |
| `db_path(id)` | 已登记身份的数据库路径，不接受任意目录 |

`CharacterError(message,status=400)`可映射为HTTP错误；不存在404、状态冲突409、迁移不可用503。

当前角色归档或删除前必须先选择其他可用角色；不能删或归档最后一个可用角色。应用负责先取消该身份的生成/动作，取得全局切换锁，再改变当前指针。仅调用本目录API并不证明旧音频已停止。

## 旧数据迁移

首次初始化在SQLite写事务内创建唯一初始角色。若根目录存在`companion.db`，通过只读URI打开旧库并使用SQLite backup生成新身份数据库，包含已提交WAL内容。成功后才提交当前角色指针；失败清理新目录并保留原库。

旧库不删除、改名、覆盖或重新写入。它是保留快照，应用此后不应再写根目录旧库；迁移后旧应用产生的新记录不会自动合并。升级前应停止旧进程并保留备份。本模块不改变原文件权限，源连接使用`mode=ro`。

旧库的合法settings.name用于保留原角色显示名；无旧库时采用“陪伴角色”描述性占位。不能从迁移显示名推出产品命名已确定。

## 删除和恢复

永久删除先把身份目录原子移至根目录内受控trash，再提交元数据删除。提交失败时把目录移回。提交成功后的磁盘清理若失败，返回`cleanup_pending=True`并保留重试记录，不谎报全部数据已清除。

初始化和新建时会尝试清理待删除数据；应用也可显式重试。此行为是逻辑文件删除，不承诺对SSD或外部备份安全擦除。资产若由外部资源库管理，仍须由应用核对引用并清理；本目录不会删除其他身份的共享资产。

## 实际验证

执行：`PYTHONPATH=src python -m unittest discover -s tests -p test_characters.py -v`。

24项测试实际通过，使用独立临时目录和真实SQLite/文件操作，覆盖：一次迁移、已提交WAL、源库保留、独立新库、外观切换不改变私聊、跨实例并发与额度、归档/恢复/最后身份保护、删除事务回滚、清理失败回执和重试、路径/链接/丢失库拒绝及POSIX权限。

本轮0.290秒是一次测试运行时间，不是性能验收。尚未覆盖所有系统故障、断电恢复或完整UI/HTTP切换；应用层请求上下文与锁集成须另验收。没有运行第三方角色、联网、提交或推送。

## 集成注意

每个请求及后台任务应固定角色ID和数据根目录，避免一次操作中途因全局active变化而转到其他身份。多角色数据库隔离不能替代HTTP鉴权、角色/资产/generation关联与单播放拥有者。

重命名应先以`validate_name`校验，再在应用的切换/写入锁下同步settings与目录。目录中不存在名字白名单；重复名字合法，身份始终由UUID确定。
