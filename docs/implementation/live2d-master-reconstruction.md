## 找到的流程风险

scripts/assemble_live2d_head.mjs 将分别生成的眼嘴部件按固定 box 用 fit:fill 缩放。
这可能造成五官与脸部的比例、透视和质感不一致。文件存在和模型参数齐全不能证明画面统一。
本轮在实际 PSD 打包入口加入固定母稿的重组核对，避免带明显偏差的分层稿无声进入后续制作。
没有直接把旧模型替换为一张不具备动作能力的 PNG。

## 新分层的要求

在原有 original-live2d-layers-v1 manifest 中加入：

```json
{
  "neutral_reference": {
    "file": "master.png",
    "sha256": "<该母稿文件的实际SHA-256>",
    "regions": {
      "face": [480, 380, 340, 320],
      "hands_cup": [610, 900, 420, 340]
    }
  }
}
```

上面的区域只是 1137×1383 候选的配置示例，制作正式图层时必须按真实画布确认。
参考必须为同尺寸 PNG，路径在源目录内。角色透明分层应对照相同透明角色母稿；如果母稿带背景，必须以同一背景完成重组后对照，不能把人物透明稿直接与带背景原图比较。
裁切图层只改变偏移，不应把眼嘴按不同长宽比拉伸。

正常导出：

```sh
python scripts/avatar_live2d_source.py pack --layers path/to/layers.json --output path/to/new-source.psd
```

此入口默认要求固定母稿。已有历史数据复现可以显式加 --allow-unreviewed-source；结果仍记 NOT_RUN，不代表审美通过。
底层 write_psd API 为兼容既有调用默认不要求合同，新的制作调用必须传 require_reference=True；一旦 manifest 提供 neutral_reference，即使兼容调用也必须验证它。

检查在 PSD 文件创建前执行：
- 母稿 SHA-256 和画布尺寸必须一致；不允许缩放参考来凑合。
- 重组画面分别在黑、白底上对照，避免漏掉透明边缘或黑色部件上的洞。
- 全图、脸、手杯各自检测：平均最大通道差 <= 2/255，最大通道差超过 16/255 的像素比例 <= 0.5%。
- 这些容差用于同源分层的编码/合成微差，是工程保真阈值，不是审美评分；不用于把重新绘制的图与用户参考图逐像素强行匹配。
- 小区域缺陷可以单独阻止导出；完全透明像素下不可见 RGB 不制造误报。
- 通过只记录 passed_reconstruction_only，art_quality_acceptance 保持 NOT_CLAIMED。
