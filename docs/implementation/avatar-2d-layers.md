# Original 2D character and optional layer package

Updated 2026-11-12. This document distinguishes working code from accepted artwork.

## Current deliverable

The user rejected the procedural 3D reconstruction and explicitly selected 2D.
Rejected geometry, its builder and renders were isolated in the ignored
`.build/rejected-3d-reference/` directory. They are excluded from source delivery,
default roles and release artifacts. Do not display those rejected images again.

Four new full-character PNGs are stored in `assets/character-2d/`. They were copied
unchanged from ImageGen outputs generated by the parent from the fresh reference.
They show the reference's short dark hair, cream sweater and held mug. Their SHA256,
dimensions, transparency measurements and generation identifiers are recorded.
They are four complete pictures with eye/mouth variants, **not independent cut layers**.

Actual `AssetStore.import_png_states`, `get` and every `resolve` succeeded in a
temporary data directory. Native canvas is 1070×1470; four frames total 6,291,600
pixels and normalized output including thumbnail is 7,119,507 bytes. The existing
PNG limits were retained. No changes to the artwork were used to pass import.

Read-only alpha-premultiplied comparison found small but nonzero body/hair changes
between generated frames. Mean absolute RGB difference outside the approximate
eye/mouth region is 6.564/4.668/7.328 out of 255 for talk/blink/talk_blink versus
idle. These numbers do not prove visual continuity; the real browser state-switch
review determines acceptance. Details, ROI and thresholds are in the measurement JSON.

## Optional PNG eye/mouth animation regions

Generated whole images differ outside the face. PNG states therefore accept
optional `animation_regions` metadata, a single object rather than an array:

```json
{
  "eyes": {"x": 490, "y": 290, "width": 235, "height": 95, "feather": 10},
  "mouth": {"x": 550, "y": 430, "width": 135, "height": 70, "feather": 10}
}
```

These coordinates were proposed by the independent QA agent after inspecting the
four actual 1070×1470 states in Chrome. Feathered boundary/real playback acceptance
is separate; these are manually reviewed image coordinates, not detected landmarks.
At least one of `eyes`/`mouth` is required when present. Values are integer pixels;
rectangles lie inside the common canvas, cannot overlap and total at most 30% of
canvas. Feather defaults to zero and is bounded by both 16 pixels and one quarter
of the smaller rectangle dimension. Unknown fields, booleans, fractions, NaN and
oversized clips are rejected before image decoding. Absent/null metadata retains
legacy whole-frame updates. The browser keeps idle as its base and blends real
state pixels only inside the masks; this is not a new cut-layer asset.

`revise_png_animation_regions(asset_id, regions)` imports a new preview revision
from canonical state resources. It never overwrites the original manifest/PNGs
or activates an appearance. Null removes metadata in a new revision. The parent
exposes `/api/characters/assets/regions`; preview and activation remain separate.
Tests compare every normalized PNG byte before and after a region revision.

## Optional layered-2d v1 input

Working backend: `AssetStore.import_layered_2d(data, filename, cancel_event=...)`.
This supports original bounded 2D layer animation without Cubism Core. It must
never be described as importing or producing a `.moc3` model.

The ZIP root contains only `layered2d.json` and lowercase PNG filenames. It must
contain genuine transparent layers supplied by the artist. Every PNG has the
same canvas dimensions; pixels are not silently cropped, resized or repositioned.

```json
{
  "format": "companion-layered-2d",
  "version": 1,
  "canvas": {"width": 1024, "height": 1536},
  "layers": [
    {
      "id": "body",
      "role": "body",
      "file": "body.png",
      "pivot": [512, 1050],
      "states": ["idle", "talk", "blink", "talk_blink"],
      "motion": {"breath_y": 2, "sway_degrees": 0.3, "gaze_x": 0, "gaze_y": 0}
    },
    {
      "id": "head",
      "role": "head",
      "file": "head.png",
      "pivot": [512, 600],
      "states": ["idle", "talk", "blink", "talk_blink"],
      "motion": {"breath_y": 2, "sway_degrees": 0.3, "gaze_x": 3, "gaze_y": 2}
    }
  ]
}
```

Array order is draw order, back to front. `pivot` uses canvas pixels from the
top-left. Allowed roles are `body`, `head`, `hair_back`, `hair_front`, `eyes_open`,
`eyes_closed`, `mouth_closed`, `mouth_open`, `accessory`. Exactly one body and one
head are required, each visible in all states. Hair is also present in every state.
An accessory may use a nonempty subset. Repeated IDs or source files are rejected.

Eye layers are optional but must be provided together: `eyes_open` is visible in
idle/talk; `eyes_closed` in blink/talk_blink. Mouth layers are also an optional
pair: `mouth_closed` in idle/blink; `mouth_open` in talk/talk_blink. Missing pairs
result in false blink/talk capabilities; the importer does not synthesize them.
Artists must remove baked eyes/mouth from the underlying head layer when supplying
these separate parts. Structural validation cannot certify that artwork operation.

Motion is declarative and defaults to zero. `breath_y` is 0–12 pixels;
`sway_degrees` 0–3 degrees; `gaze_x`/`gaze_y` 0–16 pixels. These are bounds for
small motion, not programmable callbacks, mesh physics or verified eye tracking.
The renderer must respect reduced-motion preferences and its own visibility limits.

## Canonical output

The returned/stored asset manifest has `format: "layered-2d"`, `canvas`, `width`,
`height`, `layers`, `resources`, `model`, `thumbnail`, empty `states: {}`, truthful
capabilities, `live2d: false` and `art_review: "not_run"`.
Layer filenames become canonical `l0000.png`, `l0001.png`, etc., under each UUID
revision directory. A layer uses the `resource` field instead of source `file`.
`model.resource` is `layers.json`; `resources` maps canonical PNG names to byte/SHA
descriptions. Server URL decoration and browser rendering are separate integration
work owned by the parent/frontend agents.

The idle thumbnail composites only downscaled layers. Imported PNGs retain their
decoded RGBA values through the existing safe normalizer. Source filenames cannot
choose storage paths. All files publish atomically as a new revision; failed or
cancelled imports clean staging and leave older revisions untouched.

## Limits and actual tests

At most 16 layers, 4096 pixels per edge, 8 million pixels per canvas and 32 million
total decoded pixels. ZIP and expanded/normalized resources are each capped at
32 MiB; individual PNGs 4 MiB, JSON 64 KiB, compression ratio 200. A maximum sized
set of decoded RGBA textures corresponds to roughly 128 MB before renderer/GPU
overhead; this is a budget calculation, not a measured RTX 4060 result. Actual
upload/decode/frame-time and memory costs still require browser/Windows measurements.

Executed tests include real ZIP/PNG persistence, independent body/head/eye/mouth
test layers, thumbnail composition, restart/get/resolve/delete, unsupported paths,
duplicate entries, symlinks, scripts/unknown fields, NaN, invalid/bool dimensions,
empty/opaque/identical images, mismatched canvas, budget checks before decode,
early/midway cancellation, disk/write/publish failures and manifest tampering.
The original PNG-state suite also passed unchanged. The synthetic fixture in
`.build/layered-2d-smoke/TEST_ONLY_INDEPENDENT_LAYERS.zip` tests format behavior;
it is never a candidate user character or part of a release.

The current high-quality character has **no accepted independent layer set**.
Do not populate this format by duplicating or arbitrarily chopping its four full
state images. A future true layer set requires artist inspection of head/body
separation, hidden-area fill, eye/lip matching, hair-edge alpha, matching motion
pivots, state transitions, neutral/green/window backgrounds and small desktop size.
