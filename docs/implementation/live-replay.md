# 公开事件离线入口与回放

状态：2026-11-12，本地实现与单元验证完成。未连接B站、弹幕姬、OBS、模型或私人数据库。源码为本项目独立实现，没有复制上游接入代码。

## 本轮范围

`src/companion_runtime/live.py` 提供来源/房间固定的公开文本入口、有界FIFO、稳定ID去重、过期丢弃及统计。它是后续SDK适配器之后的内部边界，不能直接解析真实平台或弹幕姬的原始消息。

房间和来源只能由可信配对/配置层构造 `LiveBinding`。这不是账号准入证明；当前模块未实现凭证认证或配对服务。调用方必须保证只能从已获授权的来源向对应入口提交事件。

模块不导入应用服务，不读取私聊、记忆、设置或凭证，不提供执行工具。观众的“记住”“我是主人”“攻击玩家”只保留为不可信文本，没有相应执行路径。后续公开模型调用仍须独立审查，不得把本模块输出传给私人 `chat()`。

## API与输入

```python
from companion_runtime.live import LiveBinding, LiveIngress

queue = LiveIngress(LiveBinding('danmuji-bridge', '123'))
status = queue.submit({'room_id': '123', 'event_id': 'fixture-1', 'text': '你好'})
event = queue.pop()  # 无事件时返回None，不等待模型或网络
stats = queue.snapshot()
```

`source` 只允许 `bilibili-open-live` 或 `danmuji-bridge`，表示可信构造层选择的入口类型。两者目前使用完全相同的内部输入格式，并不表示真实SDK已经联调。

| 输入字段 | 约束与映射 |
| --- | --- |
| `room_id` | 必填字符串；与绑定房间完全匹配。房间绑定只允许1–32位ASCII数字，避免长数字被浮点转换 |
| `event_id` | 必填，1–160字符；无首尾空格或控制字符。SDK/桥接器必须提供稳定ID；当前不自动制造指纹 |
| `text` | 必填非空字符串，最多300字符；仅支持文本弹幕，不解释其中指令 |
| `actor_key` | 可选，最多160字符；`null`、空字符串和字符串`0`转换为匿名，不当作共享已认证身份 |
| `event_at` | 可选Unix秒数；必须是有限非负数。超过接收墙钟5秒视为无效；可信时间可缩短TTL，不能延长 |
| `type` | 可省略或为`danmaku`。礼物、SC、工具等其他事件类型本轮不支持 |

所有其他字段均拒绝，包括 `source`、`channel`、`role`、`owner`、`tools`、`settings` 和 `private_memory`。来源由绑定赋予，不能由JSON自行提升。实际SDK应通过显式映射取出以上字段，不把整份平台消息直接转发。

`submit()`返回 `accepted`、`duplicate`、`expired`、`full`、`dedupe_full`、`invalid` 或 `wrong_room`。验证错误只包含固定原因码，不回显观众文本。队列事件不可变；默认统计不保存或返回正文与观众ID。

## 边界与性能取舍

默认队列200条，接收TTL为8秒，去重缓存最多4096项，保留60秒。队列满时丢弃新事件，不替换已经接纳的候选；上层仍需实现选题、冷却和“1活动任务+2候选”，本轮不实现推理调度。

去重缓存只记已接纳事件。缓存满时拒绝新事件并增加 `dedupe_full`，不淘汰未到期ID，否则重复事件可能再次被接受。过期清理不会延长事件寿命。`pop()`立即返回当前可用事件，但不表示已经生成、播出或被观众听见。

源时间戳可使较晚入队事件更早过期，清理因此检查整个有限队列，而不能只检查队头。每次操作的清理工作上限由队列和去重容量限制，不随历史事件总数无限增长。

统计定义：

- `admission_coverage = accepted / submitted`：接纳数占全部提交数，分母包括重复/无效/过期输入。
- `dequeue_coverage = dequeued / submitted`：交给下游的事件数占全部提交数；不是完成播出的覆盖率。
- `expired`：提交时已过期；`expired_queued`：接纳后在等待中到期。
- `full`、`dedupe_full` 分别报告，避免把丢弃隐藏成低延迟。

没有源时间戳时，只能从接收时计算TTL，不能证明消息在上游从未积压。去重范围仅为一个实例的来源/房间；不支持双主入口跨来源去重。重启会清空队列与去重缓存，上游重发的历史消息可能重新出现，需在真实接入层加场次/重连边界。

## 实际修正与未完成项

独立审查发现：孤立Unicode代理码点可使事件ID哈希时UTF-8编码异常；超大整型时间戳可使 `math.isfinite` 抛出溢出。已在所有公开字符串边界拒绝无法严格编码的输入，并将数值溢出归为无效输入。新增回归同时检查拒绝后正常消息仍可接收。

初始1024项/60秒去重预算在此回放中先耗尽，导致部分合成秒无法取得事件。已调整默认去重容量为4096，保留满缓存拒绝策略和专门测试。不能为了让覆盖率更高而静默淘汰有效去重ID。

尚未完成：官方账号或桥接配对认证、真实字段映射、稳定原生ID取得、礼物/SC处理、重连场次边界、公众模型上下文、语音与字幕输出、OBS音轨、目标机持续资源测试。当前检查不证明这些能力可用。
