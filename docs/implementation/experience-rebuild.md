# 陪伴场景与用途流程重建

更新：2026-11-12。本文描述当前源码与实际测试边界，不能替代最终独立验收。

## 信息架构

主屏只有一个角色场景与一条交流输入。对话回看是可关闭侧层；角色工作室提供自主身份、性格与形象导入。对话连接、声音、分享边界、设备与通信分别使用独立用途流程。旧六导航、旧任务管理页与旧通用设置表单已从 HTML 移除，没有隐藏旧表单桥。

日程从明确输入生成提案，确认后才建立本机提醒。重新打开“一起做点什么”可继续未决定提案或取消已确认日程；没有来源关联的旧提醒按既存记录展示取消入口，不猜测过去对话来源。允许主动联系不会复活旧暂停提醒。

用户选择二维路线后，被否决的三维人物不再作为 UI、默认模型或测试截图材料。PNG 四状态与真正分层格式分别标识；VRM/Live2D 仍为用户自主导入能力。没有启用形象时显示空形象入口，不自动补一个固定女角色。

## 模块与边界

| 模块 | 职责 |
| --- | --- |
| companion-core | 角色 epoch、API 身份绑定、流式消息、草稿、跨窗口媒体所有者 |
| scene-controller | 真实舞台资源生命周期、PNG 缓存/区域合成/RMS、动态渲染器选择 |
| speech-controller | 单声音、迟到失效、Audio/系统语音、播放回执 |
| ui-kit / app | 原生可达控件、用途层、主题与主场景编排 |
| studio | 自主身份/人格、预检、真实预览、确认启用与修订 |
| connection-flow / sound-flow | 对话与声音的专用接入流程，密钥不进 localStorage |
| conversation-view / assistance-view | 按需回看、真实提案与来源关联卡片 |
| privacy-flow | 明确分享、设备、偏好确认、备份、本机方向估计 |
| connectors-ui | owner 操作的微信桥接与直播本机预览流程 |
| layered-2d-renderer | 原创受限二维图层渲染，不是 Cubism/Live2D |

角色切换先失效媒体与操作，再接纳新状态。停止/隐藏/原生收起取消隐藏麦克风；显示器专用输出也取消输入与分享，保留单一角色渲染器。系统语音的边界动画不能称为 PCM 幅度或音素同步。播放回执继续记录真实停止位置；原话未播完不能推测已听文字。

PNG 一个 scope 只 fetch/decode 每个状态一次，最多四个 Blob URL。真实 Audio 的 Analyser RMS 使用快速释放与滞回阈值，语音静音窗能闭嘴。眨眼与口型切换复用缓存，不重新读取大图。预览不运行音频分析；隐藏与换角色释放 URL、计时器和音频图。

可选 `animation_regions` 是已检查的 eyes/mouth 像素矩形。运行时保持 idle 底图，只羽化混合真实状态图的眼嘴裁片；原 PNG 不改像素，也不称为真正独立拆层。修改区域创建新修订，仍须预览与明确启用。

单文件 PNG 包仅提取 `format/version/states/animation_regions` 的受限数据，显式构造当前角色上传。包中的角色 id、owner、role 或权限字段不会进入请求。

自然背景为原创静态 PNG，只有场景变更时加载；没有装饰粒子、背景 RAF 或全屏模糊。二维人物不被宣称能由 Three 灯光重新照明。日夜只改 CSS，不重建渲染器或 AudioContext。原生角落窗口不显示背景或夜间遮罩。

相机与屏幕必须先取得实际系统来源并本机预览，再明确分享单帧。普通 Chrome 使用标准媒体 API；Electron 屏幕采用宿主安全预览桥，主 UI 不能绕过原生选源直接取得屏幕。面部方向为本机估计，缺组件不可用，不伪装专业眼动或身份识别；只有具有方向动作语义的分层形象才应用估计。偏好仅在用户选择真实原话并点按提取后调用模型，确认前不是长期事实。

## 仍需独立确认

完整新 IA 的独立 Chrome/原生 after、实际麦克风/摄像头与用户硬件、Windows/RTX4060、真实平台账号、目标人物表情连续性与透明边缘人工质量尚不能由上述测试证明。自然背景/四整图/有限局部动画不等同自然身体动作、真实人物拆层或物理发丝透光。Live2D 可选 SDK 的本机评估许可不推导为分发许可。

### 纯读观测校准（保持生产冻结）

独立真实 Qwen/Kokoro 整链曾在眼嘴外检测到706个像素变化。进一步负控制发现，同一 Canvas 在没有绘制、没有音频时，强制 SwiftShader 启动的第1→2次 `getImageData` 已产生完全相同706个像素、最大通道差1、alpha不变；默认 Chrome 同脚本没有此差异。第2→3次纯读全图稳定，说明不能把首次读回差归因为口型动画的区域外绘制。

生产 context 与渲染器没有为此修改。先通过连续纯读确认观测稳定，再要求状态切换的区域外仍严格0变化；没有容许1级误差。`review/png-regions-stable-readback-probe.json` 中稳定基线后口型区内9257像素变化、外区0；恢复与20次切换外区0；故意在外区写1像素被严格检出1。独立 QA 的实际 Audio 校准见 `review/png-region-stable-readback-check.json`。初次真实模型失败报告与后续重跑分别保留；这不等于忽略失败或将大块衣身ROI当成全域证明。
